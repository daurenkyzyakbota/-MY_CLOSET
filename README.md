# MyCloset

Виртуальный гардероб на Next.js App Router и React. Приложение запускается локально и работает без аккаунта и серверной базы. Сохранены дизайн MyCloset, тёмное боковое меню, шесть пунктов мобильной навигации и светлая, тёмная и системная темы. Профиль находится в настройках.

## Запуск на компьютере

Нужны Node.js 24 и npm. Откройте терминал в папке проекта:

```powershell
npm.cmd ci
npm.cmd run dev
```

Откройте [localhost:3000](http://localhost:3000). Файлы окружения для локального гардероба не нужны. Для запуска производственной сборки:

```powershell
npm.cmd run build
npm.cmd start
```

Сервер должен работать, пока открыт сайт. Текущая версия оставлена локальной; публикация на хостинге не выполнялась.

Телефон в той же Wi-Fi-сети может открыть адрес и QR-код из раздела «На устройствах». Его гардероб хранится отдельно: данные браузера на ПК не становятся общими только от подключения к одной сети. Для переноса без облака используйте резервную копию. Вход в аккаунт по обычному HTTP-адресу локальной сети недоступен: для него нужен HTTPS; на `localhost` компьютера вход поддерживается.

## Возможности

- **Аккаунт и необязательная синхронизация.** Managed Neon Auth обслуживает вход и формы регистрации, подтверждения почты и восстановления пароля. Синхронизация подключается отдельно: пользователь сначала выбирает локальную или облачную копию. При одновременных изменениях приложение предлагает выбрать версию; автоматического объединения нет.
- **Обработка фото.** Удаление связанного участка однотонного фона, выбор точки фона, ластик, восстановление и отмена шага. Обработка идёт в браузере. Это сравнение цветов, а не ИИ-распознавание одежды: сложный фон требует ручной правки. При подключённой синхронизации сохранённое фото входит в облачную копию.
- **История носки и статистика.** Отметки для вещей и готовых образов, частота носки, дата последней носки и вещи без отметок. Данные берутся из записанной истории; календарный план сам по себе не считается выходом.
- **Капсулы.** Коллекции собственных вещей и сохранённых образов с названием и описанием. Удалённые ссылки остаются видимыми для проверки состава.
- **Поездки.** Направление, даты, заметки, выбранные вещи и образы, список сборов и прогресс упаковки. Вещи образов добавляются в список при сохранении поездки.
- **Коллаж образа.** Экспорт PNG шириной 1080 px с фотографиями вещей и существующими SVG-иллюстрациями для вещей без фото. Недостающие и удалённые детали обозначаются явно; высота изображения зависит от состава.
- **Неделя образов.** Предпросмотр семи дней с выбором повода, стиля и погоды. Подбор использует собственные доступные вещи, старается сокращать повторы и объясняет ограничения. Дни без прогноза отмечаются явно. В календарь записываются только выбранные предложения одной операцией; занятые промежутки не заменяются.

Также доступны фотографии и характеристики вещей, поиск и фильтры, избранное и стирка, ручной конструктор образов, стилист по правилам, покупки с личным бюджетом, дневные и вечерние планы, профиль и настоящий прогноз Open-Meteo. Цены и наличие в магазинах приложение не придумывает; поисковые ссылки не подтверждают наличие товара.

## Данные и резервные копии

Локальный гардероб хранится в IndexedDB: база `mycloset-local-v1`, хранилище `data`, ключ `state`. Данные разных браузеров, устройств и адресов сайта независимы. Демонстрационные вещи добавляются только по явному нажатию кнопки.

Формат полной JSON-копии — **версия 5**. В неё входят профиль, вещи и фото, образы, календарь, покупки, история носки, капсулы и поездки. Копии версий 1–4 проходят проверку и преобразуются без удаления прежних записей. Повреждённые данные отклоняются. Тема и фильтры списков остаются настройками браузера и в копию не входят.

Импорт заменяет локальный гардероб после подтверждения. Импорт и локальный сброс отключают синхронизацию, сохраняя облачную копию. Само отключение синхронизации также сохраняет обе копии. Очистка данных браузера удаляет локальные данные, поэтому резервную копию стоит хранить отдельно.

Записи выполняются последовательно; интерфейс обновляется после успешного сохранения. Если браузер запретил хранение, показывается предупреждение о временном сеансе. Для погоды, поиска товаров и облачных функций требуется интернет.

## Необязательное облачное подключение

Для локальной работы этот шаг можно пропустить. Для облака нужны проект Neon Postgres, настроенный Managed Neon Auth и серверные параметры из [.env.example](.env.example):

- `DATABASE_URL` — подключение к базе облачных гардеробов.
- `NEON_AUTH_BASE_URL` — адрес Managed Neon Auth.
- `NEON_AUTH_COOKIE_SECRET` — секрет cookie длиной не менее 32 символов.

Значения задаются в локальном `.env.local`; они не должны попадать в Git или архив исходников. После настройки базы выполните `npm.cmd run db:setup`, затем перезапустите Next.js. Команда последовательно применяет две идемпотентные миграции из `db/`.

Вход в аккаунт не загружает гардероб в облако автоматически: сначала нужно подтвердить выбор копии в разделе «Аккаунт». Синхронизация передаёт полный гардероб при изменениях. Проверка неизменившейся версии получает только метаданные, без повторной загрузки фото. Запись проверяет ожидаемую ревизию, чтобы устаревшее устройство не перезаписало новую копию незаметно. Аккаунт на телефоне по HTTPS в этой локальной поставке отдельно не проверен; настройки защищённых cookie не ослаблены.

## Устройство проекта и проверки

Next.js 16.4.2, React 19.3.1, Material UI 9.5.0, Emotion и Bootstrap 5.3.8 закреплены в `package-lock.json`. MUI предоставляет общие кнопки, поля и диалоги через App Router cache provider; Bootstrap используется для сеток и утилит, без Reboot и Bootstrap JS.

`app/` содержит страницы и серверные маршруты, `components/` — интерфейс, `lib/` — формат данных, хранение и правила, `tests/` — автоматические проверки. `db/` и `scripts/setup-cloud.mjs` нужны только для настройки облачной базы.

```powershell
npm.cmd test
npm.cmd run build
```

Подробнее: [связи файлов](docs/STRUCTURE.md), [объём выполненных проверок](docs/CHECKS.md), [исходное ТЗ](docs/TZ.md).
