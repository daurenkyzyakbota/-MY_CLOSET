# Проверка зависимостей — 6 ноября 2026

`@neondatabase/auth@0.6.0-beta` и его необязательный для нашего интерфейса пакет `auth-ui` фиксируют Better Auth 1.7.6 и Zod 4.5.4. Они входят в диапазоны опубликованных уязвимостей. Для этих транзитивных зависимостей в `package.json` установлены точные `overrides`:

- Better Auth, `@better-auth/core`, `@better-auth/passkey` и `@better-auth/api-key` — **1.7.7**, одна согласованная версия. Она исправляет [подмену Magic Link через OAuth state](https://github.com/better-auth/better-auth/security/advisories/GHSA-965c-763c-88jm) и [подмену пользователя в OAuth Proxy](https://github.com/better-auth/better-auth/security/advisories/GHSA-r4xp-prcw-77qf). По сведениям разработчиков, исправление не требует изменения публичного API или схемы пользователей. Эта версия сохраняет используемые SDK версии `better-call@1.4.0`, `@better-fetch/fetch@1.3.2` и `@better-auth/utils@0.4.2`.
- Zod — **4.6.6**, исправление [чрезмерного потребления памяти при проверке коллекций](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5).
- Для совместимой сборки Sites также закреплены исправленные версии [source-map-js 1.2.2](https://github.com/advisories/GHSA-68fv-2mgg-jv7q), [fast-uri 3.1.9](https://github.com/advisories/GHSA-w74x-v6f9-j3xg) и [baseline-browser-mapping 2.11.0](https://github.com/advisories/GHSA-w5vr-8v7q-w6rv). Все три версии укладываются в диапазоны родительских зависимостей. В собранном Worker эти инструменты не импортируются; обновление защищает также подготовку сборки.

Мы используем Managed Neon Auth через официальный SDK. Приложение не запускает собственный `betterAuth()` и не подключает серверные OAuth Proxy или Magic Link плагины. Локальные обновления зависимостей не подтверждают версию серверов Managed Auth: их обновляет поставщик. SDK импортирует клиентские плагины и обработку cookie; это отличается от исполнения уязвимых серверных сценариев в самом приложении.

Обновление SDK до доступной на дату проверки версии 0.7.0-beta само по себе не устраняет эти предупреждения: она также фиксирует Better Auth 1.7.6 и Zod 4.5.4. Поэтому использовано ограниченное обновление транзитивных библиотек с проверкой приложения.

Остаётся предупреждение низкой важности о [deepmerge 4.3.1](https://github.com/advisories/GHSA-gcqx-w48m-w2h4). Исправленной опубликованной версии на дату проверки нет. Оно приходит через `auth-ui → @daveyplate/better-auth-ui → @react-email/components → @react-email/render → html-to-text`. Эти UI-компоненты, генерация писем и `deepmerge` приложением не импортируются; собственные формы используют Material UI, а письма обслуживает Managed Auth. Уязвимость не объявляется исправленной и не скрывается принудительным понижением версии.

В этом же неиспользуемом UI-поддереве есть прежний конфликт peer-зависимостей: `@daveyplate/better-auth-ui@3.4.0` фиксирует `better-call@2.0.2`, а его зависимость `@better-auth/api-key` требует ветку 1.4.x. До обновления API Key требовал 1.4.4, после согласованного обновления до 1.7.7 — 1.4.0. Поэтому установка завершается с предупреждением, а `npm ls --all` сообщает `ELSPROBLEMS`. Рабочий SDK использует свою совместимую ветку `better-call@1.4.0`. Принудительная замена major-версии в постороннем UI-пакете не выполнялась; перед использованием его компонентов это несовпадение необходимо устранить.

`scripts/prepare-hosting.mjs --dependencies` переносит те же overrides в подготовленный Sites-проект, сохраняя настройки starter, включая `miniflare.sharp`. Прямая зависимость Zod в starter также получает 4.6.6, чтобы совпадать с глобальным override и не вызывать `EOVERRIDE`.

После изменения версий выполняются `npm test`, сборка основного и размещаемого приложения и проверка аккаунта в браузере. `npm audit --omit=dev` проверяет установленные производственные зависимости; оставшиеся предупреждения нужно оценивать отдельно от реально используемых путей исполнения.

Результат обновления: `npm test` — **300 из 300**; `npm audit --omit=dev` — **0 critical, 0 high, 0 moderate, 7 low**. Семь оставшихся записей относятся к одной цепочке `deepmerge`, а не к семи независимым уязвимостям. Проверка сборок и браузера выполняется отдельно после объединения всех изменений.

В подготовленном Sites-проекте аудит может также перечислять `drizzle-kit`, `@esbuild-kit/*` и старый `esbuild` из необязательного инструментария миграций. Они не исполняются и не импортируются в опубликованном Worker; приложение использует SQL-миграции из `db/` и собственный адаптер Postgres. Эти предупреждения не объявляются устранёнными.
