# Как связаны файлы

Next.js находит страницу в `app/(closet)/.../page.jsx`, подключает общий layout и показывает React-компонент из `components/`. Название группы `(closet)` в URL не входит. Например, `/wardrobe` использует `components/wardrobe-page.jsx`. Старый адрес `/profile` перенаправляет на `/settings`.

## Страницы и оформление

Основные разделы: главная, гардероб, образы и конструктор, стилист, календарь, покупки, избранное, настройки и устройства. Добавлены `/account`, `/insights` и `/collections`; капсулы и поездки находятся на двух вкладках коллекций. Недельный подбор открывается из календаря.

| Файл или группа | Назначение |
| --- | --- |
| `app/layout.jsx` | Общий документ, локальные шрифты, стили, App Router cache provider и MUI-тема. |
| `app/(closet)/layout.jsx`, `components/mycloset-shell.jsx` | Общая оболочка, боковое меню, верхняя панель и шесть пунктов мобильной навигации. |
| `components/ui.jsx`, `components/app-button.jsx` | Общие диалоги, поля, кнопки, значки и иллюстрации вещей. |
| `components/ui-theme-provider.jsx`, `components/theme-picker.jsx` | Светлый, тёмный и системный режимы; инициализация темы до отображения страницы. |
| `app/globals.css`, `app/themes.css`, `app/ui-libraries.css` | Исходный дизайн, оформление тёмной темы и согласование с MUI. Фото, цвета вещей и QR-код не перекрашиваются фильтрами темы. |
| `app/bootstrap-layout.css`, `app/device-access.css` | Bootstrap-сетки и интерфейс подключения устройств. Подключены только CSS сетки и утилит, без Reboot и Bootstrap JS. |
| `app/account.css`, `app/wardrobe-life.css`, `app/collections.css`, `app/media-tools.css` | Оформление аккаунта, статистики, коллекций, поездок и инструментов фото. |
| `components/use-list-preferences.js`, `lib/list-preferences.js` | Проверка и восстановление фильтров в sessionStorage; параметры ссылки имеют приоритет. |

Профиль остаётся в настройках. Режим оформления сохраняется под ключом `mycloset-theme-mode` и синхронизируется между вкладками браузера. Запрет localStorage не блокирует страницы.

## Локальное состояние и новые инструменты

| Файл | Назначение |
| --- | --- |
| `components/closet-provider.jsx` | Общее состояние и действия страниц; сохраняется при переходах между разделами. |
| `lib/model.js` | Строгий формат v5, ограничения, категории и проверяемые миграции резервных копий 1–4. |
| `lib/storage.js` | IndexedDB `mycloset-local-v1` / `data` / `state`, сообщения об ошибках, временный режим и удаление прежнего кэша MyCloset. |
| `lib/closet-state.js` | Последовательные изменения; публикация состояния после успешной записи. Связанные операции, например покупка и новая вещь, сохраняются вместе. |
| `lib/wardrobe-life.js` | Отметки носки, статистика, капсулы, поездки и упаковка вещей. История хранит реальные события и сохраняет ссылки после удаления вещи. |
| `components/insights-page.jsx` | История носки, ввод отметки, частота и вещи без отметок. |
| `components/collections-page.jsx` | Создание и редактирование капсул/поездок, выбор вещей и образов, список сборов и предупреждения об удалённых ссылках. |
| `components/weekly-planner.jsx`, `lib/week-planner.js` | Условия и предпросмотр семи дней, проверка доступности, реальный прогноз для конкретной даты и мягкое предпочтение разнообразия. |
| `lib/week-plan-save.js` | Повторная проверка состава и занятости; создание образов и выбранных планов одной операцией провайдера. |
| `lib/photos.js`, `lib/photo-background.js` | Проверка и уменьшение фото; удаление связанного фона по цвету и правка прозрачности кистью. |
| `components/photo-editor.jsx` | Локальный редактор с выбором точки фона, ластиком, восстановлением и отменой. Сложный фон автоматически не сегментируется. |
| `lib/outfit-export.js` | PNG-коллаж шириной 1080 px из сохранённых фотографий и существующих SVG-иллюстраций; явные обозначения недостающих и удалённых вещей. |
| `lib/stylist.js`, `lib/outfit-weather.js` | Подбор по правилам из доступных вещей, погодные условия для даты и проверка ручного ввода. |
| `lib/shopping.js`, `lib/shopping-filters.js` | Недостающие детали, поисковые ссылки магазинов, фильтры и сортировка покупок, включая нулевой и неуказанный бюджет. |

Резервная копия v5 включает профиль, вещи и фото, образы, планы, покупки, `wearLog`, `capsules` и `trips`. Старые данные сначала проверяются по своей схеме, затем мигрируют. Удалённые ссылки в истории и коллекциях не скрываются исправлением состава. Тема и настройки фильтров не являются частью гардероба.

## Необязательное облако

Локальная IndexedDB работает без облачной настройки. При подключении Managed Neon Auth и Neon Postgres используются следующие части:

| Файл или маршрут | Назначение |
| --- | --- |
| `components/account-page.jsx` | Формы аккаунта, явный выбор локальной/облачной копии, состояние синхронизации и выбор версии при конфликте. |
| `components/cloud-sync-provider.jsx` | Сессия, согласие на подключение, отправка изменений, проверка версий и отключение при импорте/сбросе. |
| `lib/cloud-sync-client.js` | Проверка ответов, канонический хеш, план синхронизации, метаданные подключения и сообщения об ошибках аккаунта. |
| `lib/auth-server.js`, `app/api/auth/[...path]/route.js` | Серверная интеграция Managed Neon Auth и сессий. Секреты не передаются в клиентские параметры окружения. |
| `app/api/cloud/status/route.js` | Признак готовности серверной конфигурации. |
| `app/api/cloud/wardrobe/route.js`, `lib/cloud-handlers.js` | Проверка сессии, аккаунта, origin, размера и схемы; чтение и запись приватного гардероба. |
| `lib/cloud-database.js` | Параметризованные запросы Postgres с проверкой ревизии при записи. Неизменившаяся версия возвращается без снимка и фото. |
| `db/001-cloud-wardrobes.sql`, `db/002-lossless-json.sql` | Идемпотентные миграции таблицы `public.mycloset_wardrobes`; снимок хранится как JSON для сохранения всех допустимых строк формата. |
| `scripts/setup-cloud.mjs`, `.env.example` | Команда `npm run db:setup` и перечень трёх серверных настроек без значений секретов. |

Подключённый клиент проверяет облачную ревизию примерно раз в 30 секунд, пока вкладка видима, и после возврата сети/открытия вкладки. Если версия не изменилась, получает только метаданные. При изменениях передаётся полный снимок гардероба. Сравнение ожидаемой ревизии при записи (CAS) отклоняет устаревшую отправку. Разные изменения двух устройств не объединяются автоматически.

Импорт, локальный сброс и отключение синхронизации сохраняют облачную копию. Вход в другой аккаунт требует нового выбора подключения. На `localhost` вход поддерживается; на HTTP-адресе локальной сети формы аккаунта сообщают о необходимости HTTPS. Защищённые cookie SDK сохраняются без ослабления.

## Погода и устройства

Браузер обращается к `/api/cities` и `/api/weather`. Next.js проверяет параметры и использует только фиксированные HTTPS-адреса Open-Meteo. `lib/weather-service.js` создаёт сервис, `lib/weather.js` проверяет ответы и ограничения запросов, `lib/weather-client.js` обращается к серверу. Неизвестный прогноз не заменяется вымышленной температурой; доступны ручные условия и подбор без погоды.

`/api/device` и `lib/device-links.js` формируют адреса подключения. Текущий адрес имеет приоритет, известные виртуальные адаптеры находятся ниже, ручной выбор доступен. Это подсказка по адаптерам, а не проверка доступности телефона. Открытие сайта по другому адресу создаёт отдельное браузерное хранилище.

В `tests/` находятся проверки формата, хранения, новых инструментов, синхронизации и прежних сценариев. Скриншоты, браузерные профили и тестовые гардеробы находятся вне исходников. `.env.local`, зависимости и результаты сборки не включаются в Git и архив исходников.
