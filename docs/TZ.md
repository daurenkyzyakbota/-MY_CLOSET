# MyCloset — виртуальный гардероб и ИИ-стилист

## 1. Описание проекта

**MyCloset** — учебный проект адаптивного веб-приложения для организации личного гардероба, автоматического подбора стильных образов и планирования нарядов. Приложение помогает сочетать уже имеющуюся одежду, учитывать погоду и повод, а также находить недостающие элементы образа в интернет-магазинах.

**Текущий статус:** создана базовая структура проекта на Next.js, подготовлено техническое задание и настроена работа с Git/GitHub. Все описанные ниже пользовательские функции **планируются к реализации** и не заявляются как уже готовые.

## 2. Цель и задачи

**Цель:** разработать удобное, эстетичное и адаптивное веб-приложение, которое помогает пользователю рационально использовать гардероб и подбирать подходящие образы.

**Задачи:**
- реализовать каталог одежды с фотографиями, категориями и характеристиками;
- создать ручной конструктор образов и ИИ-стилиста;
- учитывать погодные условия и повод для выхода;
- определять недостающие вещи и предлагать ссылки для покупки;
- добавить избранное, календарь и личные настройки;
- обеспечить удобную работу на телефоне и компьютере.

## 3. Целевая аудитория

Приложение ориентировано прежде всего на девушек и женщин, желающих организовать гардероб, экономить время на выборе одежды и экспериментировать со стилем. Интерфейс женственный, но функции не ограничиваются одним полом.

## 4. Подробные функциональные требования

### 4.1. Виртуальный гардероб

Пользователь может:
- добавлять вещь с одной или несколькими фотографиями (JPG, PNG, WebP);
- указывать название, категорию, подкатегорию, цвет, сезон, стиль и размер;
- опционально записывать материал, бренд, назначение, заметки и дату покупки;
- просматривать, редактировать, удалять вещи с подтверждением;
- искать вещи по названию, сортировать и фильтровать по категориям, цветам, сезонам и стилям;
- отмечать вещь как любимую, недоступную/в стирке, чтобы исключать её из подбора;
- просматривать количество вещей по категориям.

**Категории:** верхняя одежда; футболки и топы; рубашки и блузки; свитеры и кардиганы; брюки и джинсы; платья и юбки; костюмы и комплекты; обувь; сумки; аксессуары. При необходимости категории можно расширять.

**Обязательные поля вещи:** название, категория, минимум один цвет, сезон (или «всесезонная»). Фото желательно, но отсутствие фотографии не должно блокировать сохранение: используется заглушка.

### 4.2. ИИ-стилист и генерация образов

Пользователь нажимает **«Подобрать образ»**, указывает повод, стиль, погодные условия (или разрешает получить их автоматически) и при желании выбирает любимую вещь, вокруг которой строится комплект.

Система предлагает несколько вариантов образов из одежды пользователя, учитывая:
- совместимость цветов, стилей и категорий;
- сезон и ощущаемую температуру;
- осадки и ветер;
- формальность и контекст мероприятия;
- предпочтения пользователя и исключённые вещи.

Для каждого образа отображаются название, набор вещей, краткое объяснение выбора и пометки о соответствии погоде. Пользователь может заменить отдельную вещь, повторно сформировать предложение, сохранить образ или добавить его в избранное.

**План реализации:** первоначально допустим алгоритм правил (категории + палитра + сезон + повод), затем подключение внешнего ИИ API. Результаты ИИ необходимо проверять на наличие вещей и допустимость сочетаний. Сервис должен корректно работать при недоступном ИИ: показать сообщение и предложить ручной конструктор.

### 4.3. Подбор с учётом погоды

- Определение города по выбору пользователя; автоматическая геолокация — только с разрешения.
- Запрос температуры, ощущаемой температуры, вероятности осадков, ветра и краткого прогноза через погодный API.
- Подбор одежды для сегодняшнего дня и выбранной даты, если прогноз для неё доступен.
- Предупреждения: прохладно для лёгкой одежды, ожидается дождь, сильный ветер и т. п.
- Возможность вручную указать погоду, если API недоступно или геолокация запрещена.
- Обновление прогноза с отображением времени последнего обновления.

**Важно:** погода на далёкие даты может быть недоступна; в этом случае приложение не должно выдавать выдуманный прогноз.

### 4.4. Подбор по случаю

Предусмотреть сценарии: **учёба, работа, свидание, прогулка, вечеринка, торжество, повседневный выход, путешествие**. Для каждого сценария применяются свои рекомендации по удобству, формальности и стилю. Пользователь может выбирать дополнительно «комфортно», «элегантно», «спортивно», «минимализм» и другие предпочтения.

### 4.5. Недостающие вещи

Если для желаемого образа не хватает подходящей вещи, система должна:
1. Сначала предложить комплект только из имеющихся вещей, если он возможен.
2. Чётко обозначить отсутствующий элемент: например, «Светлые прямые джинсы — нет в гардеробе».
3. Показать образ с визуальной заглушкой недостающей вещи, не выдавая её за собственность пользователя.
4. Объяснить, почему она рекомендуется (цвет, силуэт, сезон, повод).
5. Дать возможность добавить вещь в список покупок, заменить альтернативой из гардероба или найти в магазине.

### 4.6. Ссылки на магазины и покупки

Для недостающих элементов предусмотрены карточки рекомендаций с названием, характеристиками, ориентировочной ценой (если она доступна), магазином и кнопкой **«Перейти к товару»**.

**Механизм работы:**
- На первом этапе — заранее настроенные категории и поисковые ссылки на магазины, например Kaspi Магазин, Lamoda, Ozon, Wildberries (при наличии доступной страницы поиска и корректного URL).
- На следующих этапах — каталог реальных предложений через официальные API или разрешённые партнёрские интеграции.
- Если точный товар не найден, показывать ссылку на **поиск похожих товаров**, а не обещать наличие конкретной модели.
- При переходе магазин открывается в новой вкладке; покупка, оплата, доставка и возвраты происходят **на стороне магазина**, а не в MyCloset.
- Не показывать выдуманные цены, наличие, скидки и ссылки. Если данных нет — скрывать соответствующие поля.
- Пользователь может настроить бюджет, предпочтительные магазины, размер и цвет; добавить рекомендованную вещь в список покупок.

### 4.7. Создание и сохранение образов

- Ручное составление комплекта из вещей гардероба.
- Автоматическое формирование вариантов ИИ-стилистом.
- Название, описание, повод, сезон и превью комплекта.
- Редактирование, копирование и удаление сохранённых образов.
- Добавление/удаление из избранного.
- Отдельный статус образов: **«Полный»** (все вещи есть) и **«Требует покупки»** (есть недостающие вещи).

### 4.8. Календарь образов

- Просмотр календаря по месяцам и выбор даты.
- Назначение сохранённого образа на определённый день.
- Редактирование и удаление назначений.
- Отображение миниатюры образа на дате.
- Возможность хранить несколько вариантов на один день (например, «днём» и «вечером»).
- Предупреждение, если выбранная вещь недоступна или прогноз изменился.

### 4.9. Профиль и настройки

- Отображаемое имя, аватар (необязательно), город.
- Предпочтения стиля, любимые цвета, размеры одежды и обуви.
- Бюджет на покупки, список предпочитаемых магазинов.
- Настройки единиц температуры, уведомлений и согласия на геолокацию.
- Экспорт/удаление данных пользователя — на этапе внедрения аккаунтов и серверного хранения.

### 4.10. Главная страница

Персонализированная панель с приветствием, количеством вещей и образов, погодой на сегодня, быстрыми кнопками «Добавить вещь» / «Подобрать образ», рекомендацией дня, избранными образами и ближайшим запланированным нарядом.

## 6. Пользовательские сценарии

**Сценарий А — добавление одежды.** Пользователь открывает «Мой гардероб», нажимает «Добавить», прикрепляет фото, заполняет характеристики, сохраняет вещь и видит её в каталоге.

**Сценарий Б — образ на учёбу.** Пользователь выбирает «ИИ-стилист» → «Учёба» → «Сегодня». Приложение получает доступную погоду, предлагает несколько комплектов, пользователь сохраняет подходящий образ.

**Сценарий В — не хватает джинсов.** Приложение предлагает комплект и помечает недостающие джинсы. Пользователь видит подходящую категорию/цвет/размер, добавляет вещь в список покупок и переходит к поиску в магазине. Возвращаясь в MyCloset, может отметить покупку и добавить новую вещь в гардероб.

**Сценарий Г — календарь.** Пользователь выбирает дату, назначает сохранённый образ и позднее просматривает запланированный наряд.

## 8. Используемые технологии и планируемая архитектура

**Базовые технологии:** Next.js (App Router), React, TypeScript, Tailwind CSS, Node.js, npm, Git, GitHub.

**Предлагаемые расширения:**
- PostgreSQL и Prisma — постоянное хранение данных.
- Система авторизации, совместимая с Next.js, — аккаунты и приватный доступ.
- Объектное хранилище изображений — фотографии одежды.
- Погодный API — прогноз по выбранному городу.
- Серверная интеграция ИИ — рекомендации с защитой ключей API.
- Развёртывание на платформе с поддержкой Next.js.

**Безопасность:** проверка данных на сервере; разграничение доступа по пользователям; запрет раскрытия API-ключей в клиентском коде; ограничения на размер и тип загружаемых файлов; контроль внешних ссылок; безопасное удаление фотографий и данных.

### 8.1. Предварительная модель данных

| Сущность | Основные поля |
|---|---|
| User | id, name, email, settings |
| ClothingItem | id, userId, name, category, colors, seasons, style, size, imageUrls, availability |
| Outfit | id, userId, title, occasion, description, status, favorite |
| OutfitItem | outfitId, clothingItemId или missingItemId, role |
| MissingItem | id, category, color, size, reason, searchLinks |
| CalendarEntry | id, userId, outfitId, date, partOfDay |
| ShoppingListItem | id, userId, missingItemId, status |
| StylePreferences | userId, styles, colors, sizes, budget, city |

Связи данных проектируются так, чтобы один пользователь видел только свой гардероб, а удаление вещи не приводило к незаметному искажению сохранённых образов.

## 9. Нефункциональные требования

- **Адаптивность:** удобная работа на экранах от 320 px до широких мониторов.
- **Производительность:** оптимизация изображений, подгрузка списков и индикаторы длительных операций.
- **Надёжность:** сохранение данных между сессиями после внедрения базы данных; понятное поведение при недоступности погоды/ИИ/магазина.
- **Удобство:** максимум понятных действий без обязательного обучения; поиск и фильтры в гардеробе.
- **Конфиденциальность:** личные фото и гардероб доступны только владельцу при наличии авторизации.
- **Совместимость:** актуальные версии Chrome, Edge, Firefox, Safari, мобильные браузеры.
- **Тестирование:** проверка форм, фильтров, создания образов, пустых состояний, внешних ссылок, мобильной верстки и ошибок API.

## 11. Критерии приёмки

1. Добавленная одежда отображается в каталоге с корректными характеристиками.
2. Редактирование и удаление вещи работают, ошибка формы показывается понятным текстом.
3. Фильтрация по категории, сезону и цвету возвращает ожидаемые результаты.
4. Пользователь собирает комплект и сохраняет его в «Мои образы».
5. Сохранённый образ можно добавить в избранное и назначить на календарную дату.
6. При доступном погодном API приложение использует реальные данные, а при сбое показывает сообщение или предлагает ручной ввод.
7. Рекомендация учитывает заданные повод, стиль и погодные ограничения; отсутствующие элементы отмечаются отдельно.
8. Недостающую вещь можно добавить в список покупок, а рабочая внешняя ссылка ведёт на конкретный товар или честно обозначенный поиск.
9. Интерфейс пригоден для мобильных экранов, нет горизонтального переполнения основных страниц.
10. Пользовательские данные не доступны другим пользователям после внедрения авторизации.

## 14. Ожидаемый результат
